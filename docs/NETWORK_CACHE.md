# 网络内容缓存优化（2026-10-23）

本次在 Lumi 1.0.4 开发源码上减少插件市场和 NewAPI 请求产生的重复传输。不改变插件 API、账户权限、用量统计公式或公开版本。

## 插件市场

- 保留原有 5 分钟目录缓存与并发读取合并。手动刷新或目录过期后仍检查 `main` 最新提交；如果提交未变且目录完整，复用目录、预览和安装清单，只更新检查时间。
- 提交改变时重新读取目录树，以 Git blob SHA 和文件大小标识不可变内容。只有新内容才需要下载；不同提交、不同包路径及预览／安装流程可复用相同内容。
- 新的 `MarketFileCache` 仅在进程内保存通过原有大小和 Git blob SHA 校验的文件，采用 LRU，最多保留 16 MiB／256 项。下载中的相同内容合并；调用者和 transport 的 Buffer 都与缓存隔离。缓存预算不包含安装事务当前持有的文件和下载中的数据。
- 网络失败、大小或哈希不符不写入文件缓存。目录含诊断时，下次刷新仍重新读取目录并重试失败文件，避免把短暂故障当成完整目录永久复用。
- 退出会中止网络、清空目录和文件缓存，迟到的响应不能重新填充缓存或发布目录。缓存不跨进程保留，不添加磁盘文件。

## NewAPI

模型目录的强制刷新只撤回当前站点／地址下 `/api/status`、`/api/pricing`、`/api/perf-metrics/summary` 和 `/api/user/self` 的读缓存及相应待完成缓存任务；下一次访问重新获取这些内容。账户读缓存继续包含凭据身份和完整查询范围。

刷新模型目录不会再清空完整消费记录、衍生曲线／效率和令牌列表，因此浏览目录后返回用量页面可继续复用尚有效的历史数据。近期重叠增量拉取、显式用量刷新、登出及服务关闭规则保留。读取失败和观测缺失仍按原规则处理，不补零、不用不完整分页生成统计。

### NewAPI 令牌与历史汇总的追加优化

缓存策略集中在 `plugins/provider.newapi/services/cache-policy.ts`，通过现有账户读缓存执行，不新增后台轮询、磁盘缓存或依赖。

- `POST /api/token/<id>/key` 是读取现有密钥，不再按写操作清空所有缓存。密钥响应仍每次向站点读取、不进入 TTL 缓存，保留权限检查、旧接口回退和返回后的账户校验。
- 令牌新增、编辑、状态切换及删除路径在请求前后撤回令牌列表、账户信息、日志、用量汇总、完整历史与衍生曲线／效率／菜单详情。名称变化可能影响历史归属，因此保留这些数据的失效；站点公开状态、账户隔离的模型价格和健康度可继续使用各自有效缓存。
- 其他未知写路径继续完整失效。失败的令牌写入也撤回相关读缓存；失效中的旧请求不能重新填回缓存。
- `/api/data/self` 的完整历史分段（结束时间早于本地当天零点）缓存 30 分钟，复用已有历史 TTL；含当天的分段保持 60 秒，主窗口与菜单对相同账户和查询共用请求。历史有修订时，最长可能等待 30 分钟；显式用量刷新立即撤回缓存。
- 余额与令牌列表仍为 30 秒，价格与公开状态为 5 分钟，健康度与 `/api/log/self/stat` 为 60 秒，普通日志页为 15 秒。统计接口可能带实时 RPM／TPM，故历史选择也不延长其 TTL。

本地请求计数确认：连续读取两次密钥，仅新增两次密钥 POST；令牌写入后刷新无工具绑定的概览为 1 次写入＋5 次读取，保留 3 个站点元数据接口；90 天的 4 个汇总分段在 61 秒后只重新获取含当天的 1 段。30 天主窗口与菜单使用同范围时不重复获取汇总。上述比例只针对对应接口和操作，不代表全部站点流量。
